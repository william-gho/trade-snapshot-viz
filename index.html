Adopting SnapshotCacheTweak on the Trade page

Coin Detail already paints instantly from a local snapshot. The Trade page still shows a skeleton until 6 network calls finish. This page explains why it should adopt the same snapshot cache, what changes for the user, where the code goes, and how to add it.

1 · Why 2 · Impact 3 · Where 4 · What to cache 5 · How 6 · Risks

1 Why adopt

One gate for everything

CoinTradeStore.viewState becomes .complete only in mapTradeInfoSuccess, after the whole task group finishes. The slowest call decides when the user sees the screen.

Most of it rarely changes

Order types, tick size, decimals, fees and limit-price bands (stored as percentages) stay the same from one day to the next. Only price, exchange rate and balance change.

Same pattern, already proven

The engine (expiry, capacity, memory warning, off-main writes) is already written and tested. Trade only needs a small adapter, like CoinDetailSnapshotTweak.

The rule (from the Confluence doc): if a stale value could mislead the user or send them to the wrong place, it doesn't go in the cache.

5 How to adopt — 5 steps

  1. Adapterkey + strip, new file
  2. RegisterDI + logout wipe
  3. Readseed in getTradeInfo
  4. Writesave on success
  5. Gate UI + testBeli waits for live
// AJCoinTradeUtil/Data/TweakPersistent/CoinTradeSnapshotTweak.swift
import AjaibDomainData
import AjaibTweak

public struct CoinTradeSnapshotModel: Codable, Equatable, SnapshotCacheEntry {
    public let assetID: String
    public let quoteCurrency: String
    public let cachedAt: Double
    public let tradeInfo: CoinTradingInfoResult          // live fields stripped
    public let orderTypes: CoinSettingTransactionType?   // highRisk NOT kept
}

public enum CoinTradeSnapshotTweakPersistent: String, TweakPersistentProtocol {
    case coinTradeSnapshot
    public var persistentType: TweakPersistentType { .soft }
}

public protocol CoinTradeSnapshotTweak {
    func get(assetID: String, quoteCurrency: String) -> CoinTradeSnapshotModel?
    func set(assetID: String, quoteCurrency: String,
             tradeInfo: CoinTradingInfoResult, coinSetting: CoinSettingResponse?)
}

public class CoinTradeSnapshotTweakImpl: CoinTradeSnapshotTweak {
    private let cache: SnapshotCacheTweak<CoinTradeSnapshotModel>

    public init(expirationInterval: TimeInterval = 24 * 60 * 60, maxItems: Int = 20) {
        cache = SnapshotCacheTweak(
            tweakManager: DependencyContainer.resolve(),
            feature: CoinTradeSnapshotTweakPersistent.coinTradeSnapshot,
            currentTime: Date.init,
            expirationInterval: expirationInterval,
            maxItems: maxItems,
            writeQueue: DispatchQueue(label: "com.ajaib.coinTradeSnapshot.write", qos: .utility)
        )
    }

    public func get(assetID: String, quoteCurrency: String) -> CoinTradeSnapshotModel? {
        cache.get { $0.assetID == assetID && $0.quoteCurrency == quoteCurrency }
    }

    public func set(assetID: String, quoteCurrency: String,
                    tradeInfo: CoinTradingInfoResult, coinSetting: CoinSettingResponse?) {
        // Price, 24h change and exchange rates move every tick — never cached.
        cache.set(
            CoinTradeSnapshotModel(
                assetID: assetID,
                quoteCurrency: quoteCurrency,
                cachedAt: cache.currentTimestamp,
                tradeInfo: tradeInfo.strippingLiveFields(),
                orderTypes: coinSetting?.transactionType
            ),
            replacing: { $0.assetID == assetID && $0.quoteCurrency == quoteCurrency }
        )
    }
}

6 Risks & guard rails

RiskGuard
User taps Beli with stale price or balancehasFreshTradeInfo keeps Beli disabled until mapTradeInfoSuccess
First load fails behind cached contentSame as Coin Detail: only keep the page on a revalidation failure. A first-load failure still shows the error state
High-risk disclaimer skippedStrip coinSetting.highRisk. Always taken from the live response
Halted coin looks tradeableHalt comes from getCoinDetail, which is never seeded from this cache
Order types change on the server24h expiry + live overwrite on every visit; a wrong selection is corrected on success
Leaks across accountsSoft tweak, registered with AJTweakManager, and wiped on logout
Cache miss (new pair)Same as today: skeleton until the API answers, then the entry is saved
